# 콘텐츠 vs 도구 — 페이지 유형 판단 규칙

새 페이지를 만들기 전에 반드시 아래 분류를 먼저 판단한다.

## 1) 콘텐츠형 페이지 (care_guide)
- 정의: 주로 **읽는 글**. 설명, 사진, 영상, 체크리스트로 구성된다. (예: 당뇨 가정관리, 백신 후 관찰, 수술 후 안내)
- 구현: **MDX 파일**로 만든다. (`content/guides/care-guide/{slug}.mdx`)
- 이유: 비개발자도 나중에 Keystatic으로 편집할 수 있어야 하므로, 데이터(글)로 다룬다.

## 2) 도구형 페이지 (calculator / assessment)
- 정의: 사용자가 입력하면 **계산하거나 채점하는** 페이지. (예: 백신 일정 계산기, CIBDAI/QoL 평가표)
- 구현: **React 컴포넌트(코드)**로 만든다. (`components/interactive/` 및 `app/(site)/...`)
- 이유: 로직이 핵심이라 콘텐츠 편집기로 다룰 수 없다.

## 3) 도구형 페이지의 데이터 분리 규칙 (중요)
- 도구의 **로직(엔진)**과 **데이터(값)**를 반드시 분리한다.
  - 로직: 점수 합산 방식, 일정 계산 알고리즘 → 코드(`lib/`)에 둔다.
  - 데이터: 백신 종류·접종 간격, 평가 항목 문구·배점 → 별도 데이터 파일(`content/data/*.ts` 또는 JSON)로 뺀다.
- 이유: 데이터를 분리하면 나중에 문구·수치만 수정하기 쉽고, 일부는 비개발자도 편집 가능하게 열어줄 수 있다.

## 판단이 애매할 때
- "읽기"가 중심이고 입력은 단순 체크 정도면 → 콘텐츠형(MDX) + 인터랙티브 컴포넌트 삽입.
- "입력→결과 산출"이 페이지의 존재 이유면 → 도구형(코드).
- 애매하면 운영자에게 한 줄로 물어본다.

## 4) 컴포넌트 배치 및 재사용 규칙
- **범용 컴포넌트 (`components/primitives/`)**:
  - 여러 다른 질병 주제나 계산 항목에서 양식/UI를 재사용할 수 있는 모든 구성 요소는 `primitives/` 폴더에 생성합니다. (예: `OptionAdvisor`, `StatGrid`, `Checklist` 등)
- **특정 주제 도구 (`components/interactive/`)**:
  - 특정 질병이나 특정 측정 항목에만 종속되는 독자적 계산 로직이 내장된 컴포넌트는 `interactive/` 폴더에 둡니다. (예: `SRRCalculator` 등)
- **중복 개발 방지**:
  - 새 컴포넌트를 만들기 전에 반드시 기존 `primitives/` 및 `interactive/` 디렉터리를 먼저 검색하여, 거의 유사의하거나 동일한 용례가 있을 시 props를 확장하여 철저히 재사용합니다.
- **하드코딩 방지 및 Props 주입**:
  - 선택에 따라 다르게 스위칭되는 안내 패턴 등은 디자인/전환 껍데기만 컴포넌트로 만들고, 들어가는 모든 의학적 문구, 옵션명, 특정 병원 브랜드나 전화번호 등은 하드코딩하지 않고 철저히 외부(MDX 등)에서 props로 주입받도록 설계합니다. 전역 브랜드 정보는 반드시 `site.config.ts`를 참조합니다.
