# new-guide — 새 보호자 교육자료 만들기

새로운 교육자료(가이드)를 일관된 구조로 추가하는 워크플로우다.
시작 전에 `.agents/rules/`의 모든 규칙을 따른다. 특히 의학 안전 규칙(40)과
콘텐츠/도구 분리 규칙(10)을 반드시 준수한다.

## 1단계 — 운영자에게 기본 정보 묻기
아래를 한 번에 물어본다(개발 용어 없이, 친절한 한국어로):
- 이 자료의 주제는 무엇인가요? (예: "고양이 만성 신장병 가정관리")
- 강아지용 / 고양이용 / 둘 다 중 무엇인가요?
- 이건 **읽는 안내문**인가요, 아니면 **점수 매기는 평가표**나 **계산기**인가요?
  (애매하면 규칙 10의 판단 기준으로 분류하고, 확신 없으면 한 줄로 재확인)
- 근거가 되는 가이드라인/출처가 있나요? (예: "IRIS 2023") — 없으면 운영자가
  내용을 직접 줄 때까지 의학 내용을 지어내지 말 것.
- 본문 원고나 핵심 내용을 가지고 계신가요? (있으면 그걸 사용. 없으면 구조만
  먼저 만들고 의학 내용은 비워둔 placeholder로 두고 검수 요청)

## 2단계 — 유형 분류 및 위치 결정
- 콘텐츠형이면 → `content/guides/care-guide/{slug}.mdx`
- 평가/계산 도구형이면 → 로직은 `lib/`, 데이터는 `content/data/`, 페이지는
  컴포넌트로 (규칙 10의 데이터 분리 준수)
- slug는 소문자·하이픈으로 짓고, 운영자에게 확인받는다. (한 번 정하면 불변)

## 3단계 — 골든 템플릿 복제
- 유형에 맞는 `templates/` 골든 파일을 복제해 시작한다.
  (care_guide / assessment / calculator)
- frontmatter를 규칙 50의 표준대로 모두 채운다:
  title, titleEn, slug, category, species, summary, sources(최소 1개),
  updated, reviewedBy(=운영자), nextReview(=6개월 뒤 기본), guidelineVersion,
  draft(처음엔 true)

## 4단계 — 본문 작성
- 운영자가 준 내용만 사용한다. 의학 수치·기준을 임의 생성 금지(규칙 40).
- 디자인을 글에 직접 넣지 않는다(규칙 20). 강조는 `<Callout>` 등 컴포넌트로.
- 종 분기가 필요하면 `<SpeciesToggle>` 사용.
- 미디어가 필요한 자리에는 `<Figure>`/`<Video>`/`<YouTube>` 자리표시를 넣고,
  운영자에게 어떤 파일을 `public/media/{slug}/`에 넣을지 안내한다. alt 필수.
- 면책 문구는 자동 삽입되므로 본문에 수동으로 쓰지 않는다.

## 5단계 — 공통 요소 확인
- 인쇄/PDF 버튼이 자동으로 붙는지 확인(레이아웃에서 처리됨).
- slug 기반 QR 코드가 자동 생성되는지 확인.
- 점수 도구라면 저장은 반드시 `lib/storage.ts` 인터페이스만 호출.

## 6단계 — 검증 및 마무리
- 빌드를 실행해 Velite 스키마 검증을 통과하는지 확인(출처 누락, 필드 누락 시
  빌드 실패 → 고친다).
- 홈 인덱스에 새 글이 자동으로 나타나는지 확인.
- 운영자에게 "의학 내용 검수 후 frontmatter의 draft를 false로 바꾸면 발행됩니다"
  라고 안내한다.
- 작성·변경한 파일 목록과 운영자가 직접 해야 할 일(미디어 업로드, 검수)을
  체크리스트로 정리해 보고한다.

## 절대 하지 말 것
- 의학적 사실 임의 생성 금지
- 글 안에 색상/크기/인라인 스타일 하드코딩 금지
- 브랜드명·연락처·면책 문구 하드코딩 금지 (반드시 site.config.ts / 컴포넌트)
- slug 임의 변경 금지
