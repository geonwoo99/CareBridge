# redesign — 전체 디자인 일괄 변경하기 (안전장치 포함)

사이트 전체의 디자인(색·글꼴·간격·요소 모양 등)을 바꾼다. 콘텐츠가 수백 개여도
디자인 토큰과 컴포넌트만 고치면 전부 반영되는 구조다. 이 워크플로우의 핵심
목적은 **콘텐츠(글)는 절대 건드리지 않고 디자인만 바꾸는 것**이다.

## 1단계 — 무엇을 바꾸는지 확인
운영자에게 묻는다:
- 무엇을 바꾸고 싶나요? (예: 메인 색상, 글꼴, 모서리 둥글기, 특정 요소 모양)
- 전체에 적용인가요, 특정 컴포넌트만인가요?

## 2단계 — 변경 위치 판단 (콘텐츠는 제외)
- 색/글꼴/간격/그림자/모서리 등 전역 값 → `styles/tokens.css`(또는 Tailwind 설정)만 수정
- 특정 요소(체크리스트·사진틀·콜아웃 등) 모양 → 해당 `components/` 파일만 수정
- 페이지 전체 배치 변경 → 레이아웃 파일만 수정
- ⚠️ `content/` 폴더의 .mdx 파일은 **절대 열거나 수정하지 않는다.**

## 3단계 — 변경 전 안전 확인
- 작업 전 현재 git 상태가 깨끗한지(커밋되어 있는지) 확인하고, 안 되어 있으면
  운영자에게 먼저 커밋/백업을 권한다. (되돌릴 수 있어야 함)
- 변경할 파일 목록을 운영자에게 먼저 보여주고 동의를 받은 뒤 진행한다.

## 4단계 — 변경 실행
- 디자인 토큰/컴포넌트만 수정한다.
- 하드코딩된 색·px를 발견하면(규칙 20 위반) 운영자에게 알리고, 토큰으로
  바꾸도록 제안한다.

## 5단계 — 검증
- 빌드를 실행해 깨지지 않는지 확인.
- 대표 페이지 몇 개(콘텐츠형·도구형 각각)를 확인해 디자인이 일괄 반영됐는지 본다.
- content/ 폴더 파일이 하나도 변경되지 않았음을 git diff로 확인해 보고한다.
- 인쇄(print) 스타일도 함께 깨지지 않았는지 확인.

## 절대 하지 말 것
- content/ 의 글 내용을 수정하는 것
- 디자인 값을 컴포넌트/글에 하드코딩하는 것 (반드시 토큰 경유)
- 운영자 동의 없이 광범위한 변경을 한 번에 밀어붙이는 것
